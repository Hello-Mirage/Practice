# Hackathon Starter

A reusable, problem-first repository template for building hackathon projects. Start with the problem, validate who experiences it, define a small solution, and only then build.

## Quick start

1. Read [the problem statement](problem-statement/PROBLEM.md).
2. Fill in [the objectives](problem-statement/OBJECTIVES.md) and [requirements](problem-statement/REQUIREMENTS.md).
3. Capture evidence in [research notes](research/research-notes.md).
4. Sketch the system in [architecture](design/architecture.md).
5. Set up your development environment using [the setup guide](docs/setup.md).
6. Track work in [the progress log](docs/progress.md).
7. Prepare your demo with the [pitch template](presentation/pitch-template.md).

## Repository structure

```text
.
├── problem-statement/   # Problem, goals, scope, requirements, evaluation
├── research/            # User research, evidence, references, assumptions
├── design/              # Architecture and diagrams
├── src/                 # Application source code
├── docs/                # Setup and progress documentation
├── presentation/        # Demo and pitch material
├── .github/             # Issue and pull request templates
├── CONTRIBUTING.md
├── LICENSE
└── README.md
```

## The hackathon workflow

**Discover → Define → Validate → Design → Build → Test → Demo**

Keep the first version small. A working solution to one clearly defined problem is stronger than a large collection of unfinished features.
